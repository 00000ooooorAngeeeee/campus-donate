## 1 项目概述

### 1.1 背景与问题

每年毕业季，宿舍清理与离校搬离会产生大量仍可使用的物品：教材、衣物、台灯、插线板、收纳箱、体育器材。这些物品的实际去向通常是垃圾桶或楼道杂物堆。

同时，在校低年级学生存在真实的需求缺口，但两侧无法对接，原因不是"没有物品"，而是**没有可信的中间环节**：

1. **信息分散**：捐赠信息散落在班级群、楼栋群、朋友圈，很快被新消息覆盖，无法检索。
2. **无登记**：线下捐赠没有台账，谁捐了什么、东西放在哪、最后被谁拿走，全部无记录。
3. **无分类**：物品混堆在一起，领取者无法按品类或驿站定向寻找。
4. **公益不透明**：捐赠者不知道自己的物品是否真的被领走，参与感弱，二次参与率低。

本项目即为解决第 1—4 项问题而建立校内闭环。

### 1.2 一句话定位

**面向本校毕业季的闲置物品捐赠与领取平台，让每一件物品的流转都有据可查。**

### 1.3 项目目标

| 目标 | 达成方式 | 可验证结果 |
| --- | --- | --- |
| 建立可检索的物品池 | 品类 + 驿站 + 成色 + 关键词的组合筛选 | 任意关键词可在 3 次点击内定位到物品 |
| 让流转过程可追溯 | 双轨状态机 + 全量事件日志 | 任一物品可查看完整时间轴，含操作人（脱敏）与时间 |
| 提升公益透明度 | 受赠确认 + 碳减排量化 | 捐赠者可看到自己物品的最终去向与减碳贡献 |
| 降低管理方人工成本 | 审核/收货/核销三台合一 | 单件物品从登记到出库的人工操作不超过 3 次 |

### 1.4 术语表

| 术语 | 定义 |
| --- | --- |
| 批次（Item） | 一次捐赠提交所形成的一条记录，含一个总量 `totalQty`。同款多件可合并为一个批次 |
| 预约单（Reservation） | 领取者对某批次发起的占用记录，含数量 `qty`、领取码、有效期 |
| 驿站（Station） | 集中存放捐赠物品的线下点位，由管理方运营，有营业时间 |
| 余量（available） | `totalQty - reservedQty - collectedQty` 的派生值，不落库 |
| 核销 | 领取者到驿站出示领取码，管理员确认放行的动作，一次性整单完成 |
| 流转履历 | 某个批次从提交到完结的全部事件序列，按时间合并批次事件与预约事件 |
| 双轨状态机 | 批次状态与预约状态两条独立状态轨，通过"被预约"动作关联 |

## 2 用户分析

### 2.1 目标用户画像

**P1 · 捐赠者（大四毕业生）**

- 时间窗极窄：离校前 1—2 周，同时要处理退宿、答辩、行李托运
- 心态：愿意捐，但**不愿意为捐赠付出额外流程成本**；如果登记超过 1 分钟就会放弃
- 关键诉求：快速提交、不用管后续、想知道东西有没有被领走

**P2 · 领取者（在校低年级学生）**

- 预算敏感，对教材、生活用品、小家电有真实需求
- 关键诉求：能按品类找、能看到实物照片与成色、能知道去哪取、能不能占到
- 顾虑：怕白跑一趟（物品已被领走却没更新状态）

**P3 · 管理员（资助中心 / 宿管中心工作人员）**

- 兼职身份，1—2 人，日常有其他工作
- 关键诉求：审核要快、核销要快、月底能直接出统计数字交差
- 顾虑：怕系统比原来的纸质登记更麻烦

## 3 范围界定

### 3.1 范围内（本期交付）

- 响应式 Web 应用（**桌面浏览器为运行环境，1280 为设计基准**）
- 学生端 4 个页面 + 管理端 3 个页面
- 登录态与角色权限（学生 / 管理员）
- 捐赠 → 审核 → 收货 → 上架 → 预约 → 核销 → 完结的完整闭环
- 流转履历时间轴与碳减排统计
- 一套可演示的初始化数据（80 个批次，覆盖全部状态）

### 3.2 范围外（明确不做）

| 不做项 | 理由 |
| --- | --- |
| 金钱交易、议价、支付 | 与公益主题冲突，且需接入支付，风险不可控 |
| 私信 / 聊天 | 工作量极大，且不是本题闭环必经 |
| 移动端专用交互（底部导航、手势） | Q10 决议为桌面优先，仅保证窄屏布局不崩 |
| App / 小程序 / 桌面客户端 | 指南明确不强制多端 |
| 跨校、社会捐赠、物流配送 | 违反"范围明确"原则 |
| 站内消息中心 | 用状态徽标与页面提示替代，见 D7 |
| 真实身份认证对接 | 用学号模拟登录，文档说明数据为自建 |
| 深色模式 | 加分有限、耗时高，见 D5 |
| 领取资格白名单 / 配额制 | 见 Q6 决议，配额降为 P2 且本次不实现 |

### 3.3 优先级定义

| 级别 | 定义 | 处理策略 |
| --- | --- | --- |
| P0 | 闭环必经，缺一则流程断裂 | 必须完成，任何情况下不砍 |
| P1 | 显著影响体验或评分 | W3 结束前完成，否则降级 |
| P2 | 锦上添花 | 工期紧张时整体砍掉，文档中说明为"后续规划" |

### 3.4 假设与依赖

| 编号 | 假设 | 若不成立的影响 |
| --- | --- | --- |
| A-01 | 学校有 1—2 个可用的集中存放点（爱心驿站） | 需改为分布式楼栋模型，数据模型与筛选维度重做 |

## 4 业务流程

### 4.1 主流程

```
① 提交登记      学生填写品类/成色/数量/照片/驿站 → 批次进入「待审核」
② 审核          管理员逐条通过或驳回（驳回须填原因）→ 通过后进入「待收货」
③ 送达与收货    学生把实物送到驿站 → 管理员核对数量并确认 → 批次进入「在架」
④ 浏览与预约    领取者筛选 → 查看详情与余量 → 提交预约（占用 N 件）→ 生成领取码
⑤ 到店与核销    领取者出示领取码 → 管理员核销 → 数量计入已领 → 批次余量减少
⑥ 完结或继续    余量为 0 则批次自动完结；否则继续在架供他人预约
⑦ 记录沉淀      捐赠者与领取者均可在「我的记录」查看，批次履历持续累积
```

**闭环验证点**：一个批次从 ① 到 ⑥ 全过程无需线下表格与电话沟通，且每一步都有日志可查。

### 4.2 双轨状态定义

**批次轨（Item.status）**

| 状态 | 含义 | 进入条件 | 可否被预约 |
| --- | --- | --- | --- |
| PENDING 待审核 | 已提交，等待管理员核验 | 学生提交登记 | 否 |
| REJECTED 已驳回 | 信息不合规，退回修改 | 管理员驳回并填原因 | 否 |
| RECEIVING 待收货 | 审核通过，等待实物送达 | 管理员审核通过 | 否 |
| ON_SHELF 在架 | 实物已入库，可被预约 | 管理员收货确认 | 是（余量 > 0） |
| OFFLINE 已下架 | 停止供应 | 管理员下架 | 否 |
| CLOSED 已完结 | 全部被领取 | `collectedQty == totalQty` | 否 |

**预约轨（Reservation.status）**

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| PENDING 待领取 | 已占用数量，等待到店 | 学生提交预约且占用成功 |
| COLLECTED 已核销 | 已到店领取 | 管理员凭码核销 |
| CANCELLED 已取消 | 主动放弃 | 学生取消，或下架时被系统取消 |
| EXPIRED 已超时 | 超过有效期未领取 | 系统惰性判定：`now > expireAt` |

### 4.3 状态转换表

**批次轨**

| 起始 | 事件 | 角色 | 目标 | 副作用 |
| --- | --- | --- | --- | --- |
| PENDING | 审核通过 | 管理员 | RECEIVING | 写日志；记录审核人 |
| PENDING | 驳回 | 管理员 | REJECTED | 写日志；保存驳回原因 |
| REJECTED | 编辑后重提 | 学生（本人） | PENDING | 保留原驳回原因到日志；清空当前原因 |
| RECEIVING | 收货确认 | 管理员 | ON_SHELF | 写日志；可修正 `totalQty`；生成入库编号 |
| ON_SHELF | 下架 | 管理员 | OFFLINE | 写日志；**须无未核销预约**（BR-05） |
| ON_SHELF | 最后一件核销 | 系统 | CLOSED | 写日志；记录完结时间 |
| OFFLINE | 重新上架 | 管理员 | ON_SHELF | P2，本期不做 |

**预约轨**

| 起始 | 事件 | 角色 | 目标 | 副作用 |
| --- | --- | --- | --- | --- |
| — | 提交预约 | 学生 | PENDING | `reservedQty += qty`；生成领取码与 `expireAt` |
| PENDING | 核销 | 管理员 | COLLECTED | `reservedQty -= qty`；`collectedQty += qty`；写日志 |
| PENDING | 主动取消 | 学生 | CANCELLED | `reservedQty -= qty`；写日志 |
| PENDING | 超时 | 系统 | EXPIRED | `reservedQty -= qty`；写日志 |
| PENDING | 批次下架 | 管理员（触发） | CANCELLED | `reservedQty -= qty`；写日志，原因标记为"下架取消" |

### 4.4 异常流程

| 编号 | 场景 | 系统行为 | 用户可见反馈 |
| --- | --- | --- | --- |
| E-01 | 两人同时抢最后一件 | 条件更新只有一方成功 | 失败方看到「余量不足，已被他人预约」并刷新余量 |
| E-02 | 预约超过 3 天未领取 | 访问时惰性判定为 EXPIRED 并归还数量 | 我的记录中显示「已超时」，余量恢复 |
| E-03 | 同一领取码重复核销 | 拒绝，返回已核销状态与核销时间 | 核销台提示「该单已于 x 时核销」 |
| E-04 | 学生已有 2 个未领取预约 | 拒绝创建 | 提示「最多同时持有 2 个未领取预约，请先领取或取消」 |
| E-05 | 下架时存在未核销预约 | 拒绝下架 | 提示「有 N 个预约未领取，需先取消」 |
| E-06 | 收货时实际数量少于申报 | 允许修正并记录差额 | 履历中出现「收货修正：申报 5 件，实收 4 件」 |
| E-07 | 余量不足但仍提交 | 拒绝 | 提示当前余量，按钮置灰 |
| E-08 | 未登录访问受限页面 | 路由重定向到登录 | 登录后回到原页面 |
| E-09 | 学生访问后台路由 | 路由守卫拦截 | 跳转 403 页 |
| E-10 | 请求超时或服务不可用 | 请求层统一捕获 | 错误态组件 + 重试按钮 |

### 4.5 业务规则

| 编号 | 规则 | 来源 |
| --- | --- | --- |
| BR-01 | 一条捐赠记录即一个批次，可含数量；不同捐赠人的物品不合并批次 | Q1 |
| BR-02 | 审核通过不等于入库，必须经「收货确认」批次才可上架 | Q2 |
| BR-03 | 预约为整单占用，可占用 1～余量的任意正整数 | Q1 + Q3 |
| BR-04 | 同一学生最多同时持有 2 个未领取预约单（**按单计数，不按件计数**） | Q7 决议 |
| BR-05 | 预约有效期 3 天，超时自动回收数量；存在未核销预约时禁止下架 | Q8 + R2 |
| BR-06 | 核销为整单核销，不做部分核销 | R1 |
| BR-07 | 收货确认时允许修正实际总量，差额记入履历 | R6 |
| BR-08 | 领取资格为全校学生实名，不做白名单与配额 | Q6 |
| BR-09 | 物品集中存放在驿站，不做楼栋分散存放 | Q5 |
| BR-10 | 状态流转仅由后端校验，前端按钮显隐不作为权限依据 | 架构约束 |
| BR-11 | 余量为派生值，不得落库，避免三字段不一致 | 架构约束 |
| BR-12 | 碳减排量为估算值，仅用于公益可视化，不构成碳核算 | D4 |

## 5 功能需求

### F1 捐赠登记　优先级 P0

| 项 | 内容 |
| --- | --- |
| 描述 | 学生提交一条捐赠批次记录，进入待审核 |
| 角色 | 学生 |
| 前置 | 已登录 |
| 页面 | 捐赠登记 |

**必填字段（压缩到 6 项）**：标题、品类、成色、数量、送达驿站、物品描述（≥10 字）。
**选填字段**：图片（最多 6 张，单张 ≤5MB，前端压缩到长边 1280 后上传）。

**主流程**
1. 学生填写表单，表单实时校验（zod schema，与后端共用）
2. 选择图片后前端立即压缩并生成缩略图预览
3. 提交成功后展示"请将实物送至 X 驿站，营业时间 Y"
4. 跳转「我的记录」，批次状态为待审核

**异常**
- 图片超过 6 张或格式不符 → 阻止添加并提示
- 提交时网络失败 → 保留表单内容，展示重试按钮
- 数量超过 20 → 提示建议拆分为多个批次（BR-02 假设 A-02）

**验收标准**

| 编号 | Given | When | Then |
| --- | --- | --- | --- |
| AC-F1-1 | 表单为空 | 点击提交 | 6 个必填项均展示字段级错误，不发起请求 |
| AC-F1-2 | 已填 6 项 | 点击提交 | 请求成功，返回批次编号，页面跳转我的记录 |
| AC-F1-3 | 选择 3 张 4MB 图片 | 选择完成 | 每张被压缩到 ≤500KB 并出现缩略图预览 |
| AC-F1-4 | 提交成功 | 查看我的记录 | 该批次出现在列表首位，状态徽标为「待审核」 |
| AC-F1-5 | 提交接口返回 500 | 提交 | 表单内容不丢失，展示错误态与重试按钮 |

## 10 附录：碳减排估算口径

**计算式**

```
碳减排量(kgCO₂e) = Σ ( 品类单件估重(kg) × 品类单位碳因子(kgCO₂e/kg) × 已核销数量 )
```

**系数表（存于 Category 表，可配置）**

| 品类 | 单件估重 | 单位碳因子 | 单件减排量 |
| --- | --- | --- | --- |
| 教材书籍 | 1.5 kg | 1.2 | 1.8 kgCO₂e |
| 衣物鞋帽 | 0.5 kg | 10 | 5.0 kgCO₂e |
| 生活用品 | 0.8 kg | 3 | 2.4 kgCO₂e |
| 小家电与数码 | 1.2 kg | 25 | 30.0 kgCO₂e |
